## 1. Test whether the backbone uses earlier evidence

Prepare a standalone AutoDL notebook using the frozen manifest and existing decoder. Prefetch only the development clips, reuse the cached environment and weights when compatible, and complete the media/hash checks before starting paid GPU inference where possible. Start with a one-pair smoke test for shapes, canonical input equality, forced-option score extraction, fresh decoder/cache state, and deterministic replay. Check source resolution evidence on ambiguous cases before changing any pair disposition. Keep the frozen nine main pairs and all 12 disposition records.

For every main pair, run question-only and recent-four once per option order, plus two earlier frames from A with fixed recent-four and two earlier frames from B with the identical recent-four. Reuse the same recent tensors in A and B and preserve chronology. Match historical slots and visual token layouts within each pair. Change only history content in the primary contrast. Use the same two predefined orders for both branches and map output labels back to canonical option identities before scoring. Save all option scores, timestamps, per-arm input digests, predicted options, true labels, timings, and failure records. Study the two uncertain pairs separately if useful. The diagnostic is a controlled forced-choice experiment on supplied frames.

For a pair with correct options a and b, record m(H) = score(a | H, R, q) − score(b | H, R, q), where H is the earlier input and R is the shared recent input. The directional contrast is m(A) − m(B). Also report both-branch correctness, correct-direction reversals, wrong reversals, one-branch correctness and unchanged answers for each order. A deterministic identical-input recent-only control with different gold answers has zero both-branch correctness by construction. Use it to verify invariance and diagnose the direction of changes. TwinPast already introduced paired accuracy and reversal metrics, so credit those definitions. [TwinPast v2](https://arxiv.org/html/2610.41983v2)

**Proposed advancement rule to freeze before inference.** A green light for one automatic-method prototype requires at least five of the nine pairs to be correct on both branches in both option orders, across at least three verified source groups. The median directional contrast must be positive in each order. This is a spending rule for an enriched development set. A valid result that misses the criteria warrants an audit of evidence legibility, temporal validity, option-order effects and decoder capacity before deciding whether another run is justified. If no pair meets the correctness criterion and the positive-control inputs and scorer are valid, stop this candidate on the current backbone. Resolve a failed technical preflight before interpreting the outcome.

The 0.5B five-pair gate failed at 3/9. The 7B replay passed its separate capability gate, and both historical-state recoveries survived the addition of fixed recent frames. The first automatic selector did not improve robust pair count over uniform. [Automatic-selection audit](<../../docs/reports/2026-11-23 twinpast automatic selection analysis.md>)

## 2. Formulate and screen one automatic method

If the diagnostic passes, prototype a candidate that answers from the recent window and overrides it only when automatically retrieved, causally available frames support a specific alternative for the queried event or state. Restrict candidates to the current branch, at or before query time, under declared storage and scan caps. Use direct option scores mapped to answer identity because the previous prompt-based binding scores were sensitive to label order. A provisional testable rule is to compare the alternative-versus-current score margin with and without the retrieved earlier input. Require both a positive evidence-induced margin change and an alternative score above the current answer under the combined input, with thresholds fixed on development. Keep the original answer on ties and when the gate stays closed. Gold answers, annotated support intervals and the other branch are diagnostic-only inputs.

Recent-first escalation overlaps with StreamScout. Answer-specific evidence adequacy overlaps with PACE. Video contrastive decoding overlaps with MACD. Cache reconstruction overlaps with FrameBlend, and query-conditioned historical retrieval overlaps with ReKV. DVR and MKG-Attention add target-journal overlap. Compare the exact temporal-validity test, access to data, answer update, training, and cost against the closest executable prior before asserting a novel mechanism. Reuse one stable HERMES path and prototype one variant. If the mechanism reduces to known operations without a material new capability, or same-selected-frame direct decoding explains the gains, stop promotion and reassess. [StreamScout](https://arxiv.org/abs/2609.00291) · [PACE](https://arxiv.org/abs/2608.26355) · [MACD](https://proceedings.mlr.press/v306/xiao26w.html) · [FrameBlend](https://arxiv.org/abs/2610.29229) · [ReKV](https://github.com/Becomebright/ReKV) · [HERMES](https://aclanthology.org/2026.acl-long.381/)

Use recent-four as the practical reference. Use chronological history and query-relevance selection under matched candidate access, plus the nearest feasible published mechanism. Add an always-read matched-history control and a same-selected-frame direct-decode control. Include a temporal-validation ablation if the method introduces that operation. Use a four-frame final answer budget for deployment experiments where feasible. Count every frame encoded and model call across both passes, independent of the final context size. Run a short development block to measure useful corrections, regressions, gate coverage and elapsed GPU time before reserving further compute.

## 3. Freeze and confirm

Freeze code, model and dataset revisions, prompts, frame grids, thresholds, eligibility, missing-output treatment, exact primary comparator, metric and practical gain target before scoring confirmation. Justify sample size and expected interval width using development discordance, independent source groups and available throughput. Keep both branches, clips cut from the same original and near-duplicate or derived videos grouped. Exclude all 12 inspected TwinPast IDs and their overlapping sources. Record unresolved provenance and define its treatment before confirmation. Previously inspected StreamingBench results support development and historical comparison. Keep confirmation predictions and score summaries out of tuning.

Use TwinPast pair accuracy as the primary endpoint for a historical-evidence claim. Compare the frozen method against the strongest relevant matched baseline selected on development. Report absolute paired differences, source-cluster confidence intervals, exact denominator, branch accuracy, unchanged and incorrectly reversed answers, and answer-level recoveries and regressions. Resample original source groups with both branches, all conditions and option permutations together. Report predeclared secondary task and cost analyses separately. A method-improvement claim requires an interval above zero for the primary contrast and a predeclared, practically acceptable resource and regression profile. If the result is inconclusive, retain the measured uncertainty and avoid retuning on those outcomes.

For the generalization experiment, use a compatible second backbone or independently sourced streaming benchmark. A second backbone on the same footage tests backbone transfer. A different benchmark or fresh sources test source transfer. Match the wording to the tests actually run.

Log wall-clock query median and p95, stream ingestion/decode and encoder cost, memory update, retrieval and re-encoding, answer time, peak GPU and host memory, and retained disk state. Use a same-machine schedule with warmups, interleaved timing and complete cost accounting. Keep offline feature replay distinct from end-to-end latency. Pin software, hardware, annotation and model revisions. Verify a clean runner on a defined slice before the main run and re-generate the headline tables from archived paired predictions. Spend sequentially on one rented GPU. Size each next batch from measured runtime and download costs.

## 4. Assemble the manuscript and run pre-submission review

Draft the task definition, evidence-linked literature comparison and reproducibility setup now. After confirmation, lead with the demonstrated original method and its primary result. Use the earlier HERMES audits as motivation or supporting diagnostics. Fill the claim ledger from actual artifacts and check each abstract, figure, result and conclusion against it. Generate the method diagram from the frozen algorithm, the main quality/cost plot from saved tables, and the failure examples from lawful unaltered frames. Preserve Figure source data and alt text or legible labels as appropriate. Prefer the formal ACL record to the HERMES arXiv version and verify all bibliographic identifiers and version labels.

The three isolated planning reviews raised these submission blockers. Repeat the review against the completed manuscript and evidence packet before approval.

| Referee lens | Blocking issue | Evidence that closes it |
| --- | --- | --- |
| Novelty | Recent-first historical checking already has close precedents. | Pseudocode and matched evaluation isolate one distinguishable operation and its contribution. |
| Experimental design | Screened annotated histories and pair-ID exclusion do not establish a deployable benefit or source independence. | Frozen diagnostic outcomes, independently grouped confirmation, a paired primary endpoint and a same-selected-frame ablation. |
| Systems and reproducibility | Final frame count can hide repeated calls, storage and preprocessing. The historical run was audited across mixed sessions. | Matched cost protocol, a clean replay of the new runner and a versioned evidence release. |
